ANITA Assistant

A virtual assistant that answers customer questions about ANITA's products over web chat, messaging and the telephone. It answers only from the ANITA catalogue, never invents a price, and refuses medical questions. Below is what is finished, what is partly finished, and what is blocked, with the reason for each.

Working today

built, tested, and reachable by a real user
Working

Answering product questions

Price, minimum order quantity, delivery time, specifications and side-by-side comparisons, read straight from the ANITA catalogue. Every price is given with the reminder that a formal quotation is required, and a price is never guessed.

Working

Web chat

Customers can ask questions on the website and get the same answers as anywhere else. The conversation is kept, so a follow-up question still knows which product is being discussed.

Working

Messaging (WhatsApp-style)

A customer message is read, answered and logged. If the phone network delivers the same message twice, the customer gets one reply, not two.

Working

Voice through the website

A customer can speak to the assistant through their browser microphone and hear the answer spoken back, with the text chat always one tap away if anything goes wrong.

Working

Handing a customer to a person

When a customer asks for a human, or the conversation turns negative, the request is recorded and appears in an operator queue instead of being lost.

Working

Customer details

Names, phone numbers and email addresses are captured once and matched to the right person, so the same buyer is not created twice.

Working

Operator console

One screen shows whether the service is healthy, what customers have been asking, which escalations are waiting, and any message the carrier refused to deliver.

Working

Safety and quality checks

The assistant declines medical or diagnostic questions, says so plainly when the catalogue has no information rather than filling the gap, and is held to a fixed set of 70 questions that must all pass before a release is allowed.

Working

Speed of speech

Speech now runs on the machine's graphics card. Speaking an answer is about seven times faster than before, which matters when two calls are in progress at once.

Partly working

the product does most of it; one specific thing is missing
Partly

The telephone line has never taken a real call

Everything on our side is built and tested. An automated test that behaves exactly like the phone network gets a spoken answer back, and the safety checks that stop a runaway call are in place. What has never happened is a real phone ringing and a person speaking.

Why: it needs a handset and a live internet link; the phone account will not let us dial our own number, so this one cannot be automated. Interrupting the assistant, a confused caller, and the 30-minute limit on a silent call can only be confirmed by a real person on a real call.

Partly

The first call after a restart is slow

Roughly seven seconds pass before the assistant speaks on the very first call after the service starts. Every call after that begins instantly.

Why: the speech models are loaded into memory on first use. It is a warm-up cost, not a fault, and it disappears once the service has been running.

Partly

Telling the sales team by email

When a customer asks for a human, the request is recorded and visible in the operator console today. Nobody is sent an email about it yet.

Why: the email server details are not configured. This is a setting we need from you, not development work.

Partly

WhatsApp as a live channel

The ability to receive and answer a WhatsApp message is built and tested end to end. No WhatsApp number is connected to it yet, so no customer can reach it on that channel today.

Why: a deliberate sequencing decision. The written answers are being proven on web chat first, then the WhatsApp number is pointed at the same engine.

Partly

Follow-up calls to customers

The queue that would hold follow-up calls is built. Nothing dials, and no customer is called.

Why: switched off on purpose. Calling customers before the legal review finishes is not something we should do, so it stays off until that closes.

Not working, or not started

blocked for a reason outside the software
Blocked

Public launch

The assistant cannot go in front of real customers until the wording it uses to decline medical questions has been reviewed and approved.

Why: this is a legal sign-off, not engineering. Until it is given, the launch stays on hold and we do not call customers.

Not started

Production setup for scale

Today the product runs on a single database file on one machine. That is appropriate for a pilot and for everything demonstrated so far, and it is not the right foundation for a public service with many users.

Why: it needs four decisions we have not taken: which database to standardise on, whether to run one server or two, how the catalogue is loaded into it, and where that loading tool lives.

Not started

A second messaging provider

Adding another channel beyond WhatsApp is designed as a configuration change rather than new development. No additional channel is switched on.

Why: waiting on a business decision about which channel is worth adding, not on engineering.
