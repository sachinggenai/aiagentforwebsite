Everything needed to run the five-surface demo end to end — what to start, what to say, what to avoid, and the parts that will not work if you are asked for them.

01

Pre-flight — finish this before the client is in the room

Five of these are things that quietly produce a broken demo rather than an error message. None takes more than two minutes.

  • Start the stack (Section 02). The launcher mints a new public hostname every run, so do this the same day, not the day before.
  • Re-point the WhatsApp sender webhook in the Twilio Console. This is the one step the launcher cannot do for you — see Act 04. It goes stale on every restart.
  • Get the client onto the WhatsApp sandbox first. Their phone must send the join code before they can message the assistant at all. Do this before the demo, not during it.
  • Warm the voice path with one test call. The API now preloads the speech models in the background at start (about 7 seconds; look for voice warmup: finished). Make one test call anyway, before the client is in the room — never let the client's call be the first one.
  • Confirm voice is actually available — at demo time, not just at boot. The launcher checks the graphics card once. A monitor re-samples it every five seconds and will shed voice on its own if free memory drops. When it does, every call is refused as busy while chat keeps working, so the stack looks healthy and only the voice half is dead.
  • Decide your prose questions. See the caution in Act 02 — open-ended prose is the slowest path on this box.
  • Open the console in a second tab and keep it ready. It is what turns "the assistant answered" into "and here is the record of it".
Voice is the one capability that can vanish after a clean start

The instance shares its graphics card with a sibling product's language models. A capacity monitor samples the card every few seconds and walks a ladder down when free memory falls below a configured floor — voice first, then speech recognition, then the text path. Once voice is shed, calls are answered with a busy message and the microphone returns an error, while chat carries on perfectly normally. Nothing in the console log says "voice is off"; it says the lines are busy.

Check it before the demo. Open a terminal and run nvidia-smi --query-gpu=memory.free --format=csv,noheader. Below 6000 MiB means the ladder has shed voice or is about to. Freeing it means unloading whatever holds the card — usually Ollama models, which is the sibling product's working set, so that is somebody else's call, not a routine step. ollama ps lists what is loaded, and the ladder climbs back on its own about thirty seconds after memory is freed.

The second most likely thing to go wrong

The WhatsApp inbound webhook is a sender setting in the Twilio Console, not a number setting. The launcher updates the voice webhooks automatically and only prints the WhatsApp one. Re-run the stack and the printed URL changes — if you do not paste the new one into the Console, WhatsApp silently stops replying. Nothing errors. Messages just go nowhere.

02

Start the stack

cd D:\project\anitamedicalsystems\platform
.\start_services.ps1

That is the whole command. It runs preflight, mints a Cloudflare tunnel for the API, writes TUNNEL_HOST, starts the API, re-points the Twilio voice webhooks, then starts the Streamlit chat with a second tunnel of its own. Re-running it is the restart path — it clears stale port holders first.

Every URL you need is written to disk

The run prints both public hostnames and also saves them to platform\logs\urls.txt. Quick-tunnel hostnames change on every restart, so read them from there rather than reusing a link from an earlier run — an old link is dead, not slow.

Full demo — public

The command above. Both chat surfaces get a public https://…trycloudflare.com address, and the phone number routes to this instance.

Use this when the client is remote, or when you want their phone to reach the assistant.

Local only — safe

.\start_services.ps1 -Local

No tunnel, nothing published, Twilio untouched. Both chat surfaces answer on 127.0.0.1.

Use this for a screen-share demo. The client sees everything and nothing of yours is on the internet.

To leave the chat surface out entirely, add -NoStreamlit.

04

The demo, act by act

ACT 01

Streamlit chat

Works today

Open the Streamlit URL from logs\urls.txt. Ask a price question and let the answer land before you explain anything.

What is the price of the ultrasound gel?

Point at the line under the answer — it names the intent, says the answer was grounded in the catalogue, and links to the source page. Then point at the sidebar: it reports how many corpus chunks are indexed and whether the dense retrieval leg is live. A system that hides its own degradation is one you cannot trust; this one tells you.

The line worth saying out loud

Prices are never generated by the model. They are read from the product database and the quotation caveat is appended in the same function that produces the figure, so there is no code path that yields a price without it.

Optional — show what happens when it is unsure

"What are the specifications of the Medical Dry Imager?" — two products share that name (₹5,50,000 and ₹2,00,000). The assistant does not guess: it lists both and asks which one. Use this if the client asks how ambiguity is handled.

Do not ask this

"Can you give me a discount on the X-ray machine?" — it is the slowest path on this box (about 23 seconds in the 17 October run), it reaches the language model, and it still ends in a non-answer. It demonstrates nothing the commercial questions above do not answer instantly. Leave it out.

Keep prose questions short

Commercial questions — price, MOQ, delivery — never touch the language model and answer instantly. Open-ended prose does use it, and the model configured in this deployment is slower than the backend timeout on this machine. If you want to show prose, use a short factual question, and expect a pause.

ACT 03

Browser audio

Works today

Stay on the same page and tap the microphone control. The browser will ask for permission — allow it. Ask the same price question out loud.

Speech is transcribed, answered by the same engine that answers text, and spoken back. Interrupt it mid-sentence and it stops — that barge-in behaviour is worth demonstrating deliberately, because it is the thing that makes a voice assistant feel like a conversation rather than a recording.

Two honest notes

It runs over a secure connection and needs one: the public https:// address works, and so does localhost. A plain http://192.168.x.x address will not — browsers block microphone access on insecure origins.

It is turn-based: you speak, it answers, and you can interrupt. Calling it full duplex would be overstating it — the assistant does not talk while you talk.

ACT 04

WhatsApp

Needs setup

The assistant is reachable on the Twilio WhatsApp sandbox number +1 415 523 8886. Two things must be true before a client can message it.

  1. The client's phone has joined the sandbox. They send the join code as a WhatsApp message to that number. The current code is in the Twilio Console under Messaging → Try it out → Send a WhatsApp message. This is Twilio's requirement, not the product's.
  2. The sender webhook points at this instance. In the Twilio Console, go to Messaging → Senders, open the sender, and set the inbound webhook to the WhatsApp URL the launcher printed, method POST. It looks like https://<api-host>/twilio/whatsapp.

Then have the client send a price question from their own phone. The reply arrives in the same thread.

Budget for this one

The WhatsApp path is built and exercised, but no message has ever been carried over Twilio's real network — the verification so far is in-process. Your first live message is also the first carrier evidence. Test it yourself before you show it, and if it does not reply, check the sender webhook first: it is the cause almost every time.

If a reply is composed but not delivered, it is not lost — it appears in the console's Outbound sends panel with the carrier's own error against it.

ACT 05

Phone call

Needs setup

Dial +16067334470 and ask the price question when the line opens.

The caller speaks first

There is no spoken greeting. The line connects to silence and waits for you. Say your question straight away — and tell the client this in advance, because it reads as a fault otherwise.

Watch the instance window while the call runs. A healthy call logs the media stream opening, the detected start of speech, the transcript, the answer, and then the stream closing. That sequence is the demo as much as the audio is.

The one thing to be careful about

Real outbound calls have now completed end to end through this instance, including transcription and spoken answers. The inbound direction has been verified at the webhook and TwiML level, but the first real handset call to the number is still the first carrier evidence — and the interruption timing is tuned for a real handset and echo path. Make your own call before the client makes theirs.

Capacity is two concurrent calls. If a caller hears a busy message instead of the assistant, the line is full or voice has been shed under graphics-card pressure — check the card, not the code.

ACT 06

Outbound call — the assistant rings you

Needs setup

This is the direction the platform chooses rather than receives, and it is the strongest closing moment: your phone rings, and the assistant is the one making the call.

Open https://<api-host>/dialer and paste the admin token. The page lists what may be dialled, adds and removes numbers, and places the call. Type a number, press Call, and answer your phone.

Ask a verified question

Use the bank in Act 02 — "What is the price of the ultrasound gel?" or "What do you sell?". Improvised phrasing such as "provide me the list of the product" is classified as an unknown product and honestly declined; the text page does exactly the same, so it is not a voice fault.

The approved numbers, the token, and the Call button are all on one screen — which is the point of it being a page rather than a dashboard panel.

There is a terminal equivalent, for a box you are already sitting at:

cd D:\project\anitamedicalsystems\platform

.venv\Scripts\python.exe scripts\demo_call.py --list
.venv\Scripts\python.exe scripts\demo_call.py --add +91XXXXXXXXXX
.venv\Scripts\python.exe scripts\demo_call.py --to  +91XXXXXXXXXX
.venv\Scripts\python.exe scripts\demo_call.py --remove +91XXXXXXXXXX

Both are the same code underneath, so a rule cannot hold on one and not the other.

Answer it. The assistant greets you as the assistant from the company, then answers exactly as it does everywhere else — same engine, same catalogue, same price caveat. Hung up, the call is sitting in the console as a voice_outbound conversation.

A number you add is dialable on the very next call — no restart, because the check reads the list rather than a copy taken at start-up.

Expect to add --any-time, and know why

Dialling is refused outside 10:00–19:00 India time, because that is the window the follow-up feature is configured with and the dialler deliberately reuses the same rule rather than keeping a second copy that could disagree.

This machine is on India Standard Time (UTC+05:30), the same timezone as the window. Calls between 10:00 and 19:00 IST need no override; a demo before 10:00 (or after 19:00) must tick Allow outside the calling window or pass --any-time:

.venv\Scripts\python.exe scripts\demo_call.py --to +91XXXXXXXXXX --any-time

That is the correct command for a demo, not a workaround. If you would rather the rule matched your working hours, change outbound.window_start and window_end in config/anita.yaml — but do it deliberately, because those hours are the ones that protect a real buyer from being called at midnight.

Why this is safe to run in front of a client

The list of dialable numbers lives in configuration, and it is checked twice: by the command before it dials, and again by the product when the carrier asks for the call's instructions — so even a call placed by something else cannot connect the assistant to a number nobody approved. And the calling-window rule from the follow-up feature still applies: outside the configured hours the command refuses unless you deliberately override it.

What this is not

It is not the follow-up feature. The lead-driven dialling worker is still held for a legal review of calling real buyers, and nothing here changes that. This places one call, to your number, because you asked it to. Say it that way if the client asks.

05

What the assistant actually does

For when the client asks how it works, or why an answer can be trusted.

Answers from the real catalogue

141 content chunks extracted from the company's own website by an in-repo pipeline — product specifications, trade terms, FAQs, company facts.

Two retrieval legs, fused

Dense vector search and keyword search run together and are combined, with an exact-phrase override when one candidate clearly wins. If the best match falls below the confidence threshold, the assistant declines instead of guessing.

Commercial facts are deterministic

Price, minimum order quantity and delivery time are read from the product database. The model is never on that path. A field that is blank returns "not published" rather than a plausible number.

Every grounded answer is cited

Answers carry their source, and a citation check can block a catalogue update from going live — an uncited answer is treated as a defect, not a cosmetic one.

Guardrails that hold

Clinical questions are refused outright, before retrieval is ever consulted. Off-topic questions are declined. Text generated by the model is re-checked against its own source before it is shown, and rejected if a figure does not appear there.

Leads and escalation

A decline offers a callback and captures the details. Messages are scored for sentiment, and a strongly negative turn raises a handoff for a human — recorded, with the open ones visible on the console.

One conversation, many channels

Chat, WhatsApp and voice resolve to the same buyer identity, so a conversation started on the web continues on the phone.

Quality gates on the record

A frozen evaluation set is pinned by hash and verified at boot; a release gate refuses promotion if the score drops or if answers lose their citations.

06

What you cannot demo

Better to know now than to be asked live. Do not promise any of these.

CapabilityStatusWhy
Follow-up calling — the assistant ringing buyers by itself Cannot be demoed The dialling queue, its calling-window rules and its attempt limits are built and pass tests, but nothing in the running product starts a worker to drive them, and that is deliberate: proactively calling real buyers is held for a legal review. Act 06 is a different thing — one call, to a number you approved, started by hand. Do not let the demo imply the follow-up feature has arrived.
Voice, when the graphics card is contended Check first Voice is shed automatically when the shared card runs low, and the only symptom is a busy message. See the callout in Section 01 — check the card before you start, not just when you started.
A proven real phone call Unproven Inbound transport is complete and verified with a simulated carrier. No real handset call has been placed. Your test call changes this.
Email notification to a sales rep Needs setup Mail credentials are not configured on this box. Escalations are still recorded and still appear on the console — they simply stay open rather than emailing anyone. Set the mail settings to close this, or present it as the console queue it is.
WhatsApp over the real carrier Untested Verified in-process only. See Act 04.
WebRTC as the browser-audio transport Works today The channel is WebRTC when ANITA_WEBRTC_ENABLED is set — a peer connection carrying Opus, not a WebSocket carrying frames. Verified by a call that transcribed real speech. The WebSocket path is still the default and still works.
Full-duplex audio — the assistant talking while you talk Cannot be demoed Still turn-based: the assistant waits for the end of your utterance, then answers, and you can interrupt it. Simultaneous speech needs the engine's echo gate reworked — it distinguishes your voice from the assistant's playback precisely because the two never overlap. Say "interruptible", never "full duplex".
Voice notes and images on WhatsApp Cannot be demoed Voice notes are declined with a prompt to type instead. Images and PDFs are acknowledged and answered from the caption; they are not read into the catalogue.
An extra messaging channel Not configured The mechanism is built but switched off, and nothing is pointed at it. It is a configuration change to enable, not a development task.
